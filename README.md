# Journey of Ascension

## Обновление 2026-06-24

- В guided-маршруте после завершения Заднесрединного меридиана бот предлагает открыть секретное задание перед переходом к следующему меридиану.
- Секретное задание предлагает выйти на природу, сесть спокойно, по возможности спиной к дереву, и подышать всем Заднесрединным меридианом как единой линией.

Telegram-бот для постепенной внутренней практики на 4 языках: `ru`, `en`, `uz`, `kz`.

Бот помогает пользователю двигаться по двум направлениям:

- **Яма/Нияма** - нравственный фундамент практики. Бот ежедневно присылает принцип для наблюдения, чтобы постепенно внедрять его в жизнь.
- **Китайские меридианы** - следующий слой работы с вниманием, телом, дыханием и ощущением энергии. Пользователь может идти по рекомендованному пути или самостоятельно выбирать меридиан.

## Возможности

- 4 языка интерфейса и контента: русский, английский, узбекский, казахский.
- Выбор режима практики: только Яма/Нияма, только меридианы или оба направления.
- Onboarding объясняет новичку практическую логику пути: куда уходит энергия, как Яма/Нияма закрывает утечки через речь, привычки и реакции, и зачем меридианы нужны для телесного наблюдения Ци.
- Раздел Яма/Нияма уточняет, что принцип дня — это акцент для наблюдения, а не отмена остальных принципов.
- При выборе обоих направлений onboarding теперь собирает два отдельных времени: одно для Ямы/Ниямы и отдельное для меридианов.
- Четырёхшаговый onboarding для режима "оба направления" показывает честные счётчики `1/4`, `2/4`, `3/4` и объясняет, зачем меридианам отдельное время.
- Отдельная логика для меридианов: маршрут бота или свободный выбор, текущий фокус, переход по точкам кнопками, список точек с возвратом к текущей практике, понятная кнопка завершения меридиана и переход к следующему каналу маршрута.
- Маршрут бота начинается с центральных каналов и пары Шао-инь: сначала Заднесрединный меридиан, затем Переднесрединный меридиан, затем меридиан Почек и меридиан Сердца. После них идут остальные основные меридианы.
- Первый экран меридианов сделан компактным: продолжить текущую практику, начать/выбрать путь изучения, открыть справку по цуням или вернуться в меню.
- Экран настроек показывает текущий ритм практики: активный путь, язык, часовой пояс, отдельные времена Ямы/Ниямы и меридианов, дни тишины. HTML-симулятор отображает этот snapshot тоже.
- Экран "Мой путь" теперь отмечает активный режим галочкой, чтобы пользователь сразу видел, что сейчас включено: Яма/Нияма, меридианы или оба направления.
- HTML-симулятор и статический UX-превью показывают тот же активный маркер режима, поэтому локальная проверка не расходится с поведением Telegram-бота.
- В HTML-симуляторе выбор режима из "Мой путь" больше не ведёт в onboarding с часовым поясом: он повторяет поведение существующего пользователя и при необходимости открывает выбор пути меридианов.
- Справочные экраны меридианов больше не показывают кнопку текущего фокуса, если меридианная практика отключена, даже если в профиле остался старый выбранный канал.
- Ошибка при переключении режима практики теперь отвечает на языке пользователя; аудит ловит возврат английского fallback в этом callback.
- Команда `/settings` для неактивного, но уже известного пользователя отвечает на сохранённом языке профиля, а не жёстко по-английски.
- Старые inline-кнопки главного меню после остановки бота больше не открывают разделы: неактивный пользователь получает сообщение, что нужно начать заново.
- Такая же защита добавлена для старых кнопок внутри Яма/Нияма, Настроек, Моего пути и Меридианов: после остановки они не продолжают сценарий.
- Старые текстовые шаги тоже очищаются после остановки бота: пользователь не сможет случайно продолжить изменение времени, часового пояса или обычный feedback, если бот уже остановлен. Исключение оставлено только для добровольного ответа на вопрос, почему он решил остановить работу бота.
- HTML-симулятор повторяет отдельный переход настройки времени меридианов: кнопка `Время меридианов` открывает именно меридианное время, а текст различает onboarding `Шаг 3/4` и обычное изменение времени в настройках.
- Быстрый сценарий симулятора `settings` открывается с обоими активными режимами, чтобы ручная проверка сразу видела отдельные времена Ямы/Ниямы и меридианов.
- 14 меридианов и 361 точка в `bot/meridians.json`.
- Изображения для точек и обзорные схемы меридианов в `images/meridians`.
- Standalone-аудит `scripts/audit_meridian_content.py` проверяет 14 меридианов, 361 точку, 4 локали, изображения и явные хвосты исходников без запуска Telegram-бота.
- Для готовых Переднесрединного и Заднесрединного меридианов обзорные схемы привязаны в `bot/meridians.json`, а все точки `VC1-VC24` и `VG1-VG28` имеют отдельные изображения.
- Справка по системе измерений в ТКМ: как отмерять `0,5`, `1`, `1,5`, `2`, `3` и `5` цуней. При открытии справки бот отправляет локализованную схему для языка пользователя: `cun_measurement_en.png`, `cun_measurement_ru.png`, `cun_measurement_uz.png` или `cun_measurement_kz.png`.
- Для `uz` и `kz` справки по цуням временно используется английская схема, пока не появятся проверенные локализованные изображения.
- Экран меридианов даёт новичку мягкое объяснение: что такое каналы Ци, почему точки могут ощущаться открытыми или «молчать», как один меридиан связан с соседними, и где граница между практикой самонаблюдения и медициной.
- Первый экран меридианов выровнен на `en`, `uz` и `kz`: теперь он, как и русская версия, объясняет зачем изучать меридианы, как внимание/дыхание/касание помогают почувствовать точку, когда выбрать маршрут бота, зачем открыть справку по цуням и где проходит медицинская граница.
- Справка по поиску точки: как уточнять расположение через изображение, цуни, касание, дыхание и внимание. Из справки по цуням можно сразу перейти к поиску точки, не перегружая первый экран меридианов.
- Справки по цуням и поиску точки теперь связаны в обе стороны: из измерений можно перейти к поиску точки, а из поиска точки вернуться к цуням. HTML-симулятор и UX-аудит повторяют эту связку.
- Карточки точек дают не только расположение, но и практическую подсказку по области тела: живот/таз, позвоночник, грудь, голова, рука или нога.
- Подсказки по области тела защищены от ложных совпадений: аудит ловит случаи вроде `поверхности` -> `нос` и `межреберный промежуток` -> тазовая подсказка.
- Полезные позиционные подсказки из источников больше не теряются: открыть рот, поднять руку, повернуть ладонь, согнуть колено, лечь на бок или на живот теперь показываются в блоке концентрации, а не как сухой хвост в расположении точки.
- Последняя точка каждого меридиана теперь подсказывает пройти вниманием весь канал целиком, чтобы завершение было практикой интеграции, а не просто нажатием кнопки.
- Подсказка "Проверьте область" корректно обрабатывает десятичные расстояния вроде `0.5 cun` и больше не превращает их в обрубок `0`.
- В английской и узбекской локалях названия точек отображаются латиницей, чтобы карточки и списки не смешивали алфавиты и не превращались в один технический код.
- Ежедневные напоминания в локальном времени пользователя.
- Настройка часового пояса, времени и дней без напоминаний.
- Главное меню с разделами Яма/Нияма, Меридианы, режимы практики, настройки, информация о боте и обратная связь.
- В разделе Меридианы кнопка полезных материалов открывает базовые статьи и отдельную тему "Пять шу-точек". Тема шу-точек отправляется как расширенная статья: вводный блок, речная аналогия, показания и отдельные разделы по истокам, ручьям, быстринам, рекам и устьям; изображения вставлены между текстовыми блоками рядом с соответствующими номерами точек.
- Карточка каждого меридиана показывает классификацию ТКМ: Инь/Ян, стихию, парный меридиан и уровень канала. Для Переднесрединного и Заднесрединного меридианов указано, что это непарные чудесные сосуды вне пяти стихий органных меридианов.
- На вводной карточке парного меридиана есть отдельная кнопка с названием его парного канала; по нажатию открывается карточка этого меридиана с описанием, схемой и дальнейшей навигацией.
- Локализованная админская рассылка анонса обновлена: админ может отправить анонс из меню или командой `/broadcast meridians_announcement`, а каждый активный пользователь получит текст на своём языке. В тексте говорится, что исправлены баги с нерегулярной отправкой напоминаний, добавлена функция изучения китайских меридианов, а также нужно перейти в нового бота `@journey_ascension_bot`, потому что текущий бот скоро перестанет поддерживаться.
- Админская кнопка проверки напоминания теперь проверяет все активные режимы пользователя: если включены и Яма/Нияма, и Меридианы, бот отправляет оба тестовых сообщения.
- Повторный `/start` после паузы практики больше не ломает onboarding: неактивный пользователь может заново пройти настройку времени Ямы/Ниямы, времени меридианов и дней тишины. Экран дней тишины теперь явно объясняет, что выбираются дни, когда бот не присылает сообщения, например для практики во все дни кроме воскресенья нужно выбрать только воскресенье.
- HTML-симулятор без Telegram и автоматические UX-аудиты для текстов, кнопок, картинок, callback-логики и локалей.
- Быстрые сценарии HTML-симулятора для ручного прогона новичка: перед стартом меридианов и первая точка первого меридиана.
- Быстрые ссылки симулятора принимают сценарий и через query, и через hash: `?scenario=measurements` или `#scenario=measurements`. Это удобно для локальной проверки без Telegram и без влияния на реальных пользователей.

## Текущий статус

- Базовый MVP ветки меридианов реализован: все 14 меридианов, все 361 точки, изображения, локализация и навигация доступны в кодовой базе.
- Яма/Нияма остаётся фундаментом: ежедневная карточка принципа показывает часть практики, живой фокус дня и конкретное действие для наблюдения.
- Раздел Яма/Нияма во всех текстовых слоях теперь прямо объясняет, что принцип дня — это акцент внимания, а не замена остальных принципов. Экран "Все принципы" звучит как вход в практику, а не как сухой каталог.
- HTML-симулятор синхронизирован с экраном "Все принципы": preview теперь показывает то же живое вступление, что и реальный Telegram-бот, а не один голый заголовок.

- Пройти руками основные сценарии в HTML-симуляторе и тестовом Telegram-боте: onboarding, выбор режима, Яма/Нияма, меридианы, текущая точка, список точек, завершение меридиана, настройки и остановка бота.
- Вычитать интро остальных меридианов и точек как пользовательские карточки практики: убрать сухие обороты, проверить длину caption и сохранить аккуратный медицинский disclaimer.
- Отдельно проверить стиль `uz` и `kz`: сейчас локали технически заполнены, но требуют редакторского просмотра на естественность.
- Усилить аудит там, где ещё остаются ручные проверки: понятные top-level кнопки, безопасная HTML-разметка, картинки для всех карточек и корректная работа расписания после смены режимов.
- Следующий UX-проход: ручная проверка раздела меридианов в тестовом Telegram-боте с новой схемой цуня, затем проход Яма/Нияма после обновления описаний принципов.
- Оценка на текущий проход: до закрытия аккуратного v1 остаётся около `30 минут` на финальные аудиты, один ручной HTML-прогон и коммит. Более глубокая редактура всех 361 точек носителями `uz`/`kz` остаётся отдельным улучшением после v1.

## Тестирование без реальных пользователей

Для проверки новых сценариев используйте отдельного Telegram-бота и отдельную директорию `data`.

Рекомендуемый порядок:

1. Создать тестового бота в BotFather.
2. Указать его токен в `.env`.
3. Убедиться, что используется отдельная папка данных:

```env
DATA_DIR=data
```

4. Запустить контейнер и написать тестовому боту `/start`.

Если контейнер не может записывать `users.json` или `bot_messages.json`, проверьте права на `data`:

```bash
mkdir -p data
chmod -R 777 data
docker compose up -d --force-recreate
```

Для тестового сервера это самый быстрый способ убрать ошибку `Permission denied` на bind-mounted JSON-файлах.

## Команды пользователя

| Команда | Описание |
| --- | --- |
| `/start` | Запустить onboarding: язык, режим практики, часовой пояс, время, дни без напоминаний |
| `/menu` | Открыть главное меню |
| `/settings` | Настроить ритм практики |
| `/stop` | Поставить практику на паузу |

Команда `/test` доступна администраторам и отправляет проверочное напоминание.

При старте бот публикует публичное меню команд Telegram на английском, русском, узбекском и казахском языках. Команда `/settings` в этом меню описана как настройка ритма практики, а `/stop` — как пауза практики, не как выключение сервиса. В публичное меню входят только пользовательские команды: `/start`, `/menu`, `/settings`, `/stop`. Админские команды намеренно не добавляются в command menu.

## Локальный UX-симулятор

Симулятор помогает проверять тексты, кнопки, изображения и сценарии без Telegram.

```bash

```

Откройте:

```text

```

Можно открывать конкретный экран сразу:

```text
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&scenario=noviceMeridians
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&scenario=noviceFirstPoint
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&scenario=current-point
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&scenario=all-points
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&scenario=choose-meridian
```

Для прямого открытия сервисного экрана можно использовать и параметр `screen`, например:

```text
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&screen=about
http://127.0.0.1:8766/tmp/ux_simulator.html?lang=ru&screen=settings
```

Важно: запускайте `http.server` из корня проекта. Если отдавать только папку `tmp`, HTML откроется, но изображения из `images/meridians` не загрузятся.

Для ручного UX-прогона новичка используйте быстрые сценарии:

- `Novice: before meridian start` - вход в раздел меридианов до выбора маршрута.
- `Novice: first meridian point` - первая точка первого меридиана с изображением и практикой.

Аудиты:


## Данные

Пользовательские данные лежат в `data/`:

- `users.json` - настройки, режимы практики, прогресс меридианов.
- `sent_logs.json` - журнал отправленных сообщений.
- `bot_messages.json` - сообщения, которые бот может удалять для чистого интерфейса.
- `feedback.json` - обратная связь.

Контент:

- `bot/principles.json` - 10 принципов Ямы и Ниямы.
- `bot/meridians.json` - меридианы, точки, локализации, источники, изображения.
- `images/` - изображения принципов.
- `images/meridians/` - схемы меридианов и точек.

## Docker volumes

В `docker-compose.yml` контент подключается так:

```yaml
volumes:
  - ./data:/app/data
  - ./images:/app/images:ro
  - ./bot/principles.json:/app/bot/principles.json:ro
  - ./bot/meridians.json:/app/bot/meridians.json:ro
```

Это позволяет обновлять контент и изображения без пересборки образа, если код не менялся.

## Важная продуктовая логика

- Старые пользователи остаются на Яма/Нияма, меридианы включаются только после выбора.
- Прогресс по точкам меридиана не двигается автоматически. Пользователь нажимает кнопки сам.
- Кнопка завершения меридиана видна на карточке меридиана и точках. Если пользователь нажимает её до последней точки, бот просит подтверждение, чтобы случайно не перескочить к следующему меридиану.
- Ежедневное сообщение по меридианам напоминает о текущем фокусе и сразу показывает кнопки навигации по практике; само оно не переключает точку без нажатия пользователя.
- Дни без напоминаний применяются ко всем активным ежедневным практикам.
- Бот не заменяет медицинскую диагностику или лечение. Меридианы используются как карта наблюдения, самодисциплины и внимательной практики.

```bash
curl "https://api.telegram.org/bot<token>/getMe"
```

Если после `git pull` интерфейс не изменился, пересоздайте контейнер:

```bash
docker compose build --no-cache

```

Если менялись только JSON или изображения, обычно достаточно:

```bash
docker compose up -d --force-recreate
```
